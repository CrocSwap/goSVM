# SDK-2 Token and Token-2022 CPI probe

This experimental fixture exercises the checked instruction builders in
`gosvm/sdk/token` through real CPIs. Instruction data names the account
indices, so one program covers both token programs:

- Token-2022, following Hyperlane's synthetic warp route: a 234-byte PDA mint
  created by the program, `InitializeMetadataPointer` and `InitializeMint2` with
  the mint as its own authority, a keypair token account (`InitializeAccount3`),
  a self-owned PDA escrow (`InitializeAccount` with the Rent sysvar),
  `MintToChecked` signed by the mint PDA, `TransferChecked` in and out of the
  escrow, `BurnChecked`, `GetAccountDataSize` with and without `ImmutableOwner`,
  and propagated Token-2022 errors.
- Classic Token, following the collateral route: escrow creation and
  `InitializeAccount`, checked transfers, mint and burn, and SDK rejections.

Every step asserts exact account bytes against the pinned Token-2022 8.0.0
and Token 3.5.0 images bundled with LiteSVM 0.8.2
(`third_party/litesvm-0.8.2/src/programs/elf`). `testdata/svm.json` is
generated by `TestSDKTokenCPISBF` in `internal/compiler/sdktoken_sbf_test.go`,
which also runs it on fogo-v0 and solana-v3:

```sh
go test -ldflags=-linkmode=external ./internal/compiler -run TestSDKTokenCPISBF -count=1 -v
GOSVM_UPDATE_FIXTURES=1 go test -ldflags=-linkmode=external ./internal/compiler -run TestSDKTokenCPISBF
gosvm -o build/token-cpi.so examples/token-cpi
gosvm svm-test -elf build/token-cpi.so -fixtures examples/token-cpi/testdata/svm.json
```
