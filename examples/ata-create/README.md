# SDK-2 associated token account probe

This experimental fixture exercises `gosvm/sdk/ata` and `pda.Seeds.FindAddress`
against the real ATA 1.1.1, Token-2022 8.0.0 and Token 3.5.0 images bundled
with LiteSVM 0.8.2. It follows Hyperlane's warp-route `transfer_out`: the
recipient's associated account is created idempotently and paid by a
data-less System-owned PDA (`"ata_payer"` + bump).

- Token-2022: a 234-byte metadata-pointer mint yields a 170-byte account with
  `ImmutableOwner`, rent debited from the PDA payer; repeating is a no-op and a
  non-idempotent `Create` fails with the ATA program's `IllegalOwner`.
- Classic Token with a transaction-signer payer.
- On-chain `ata.Address` and `pda.Seeds.FindAddress` match the host derivation.
- ATA rejection of a substituted address, and SDK rejections for a mint of another program, wrong PDA
  seeds, an unsigned or program-owned payer and a non-ATA program.

`testdata/svm.json` is generated by `TestSDKATACreateSBF` in
`internal/compiler/sdkata_sbf_test.go`, which runs it on fogo-v0 and solana-v3:

```sh
go test -ldflags=-linkmode=external ./internal/compiler -run TestSDKATACreateSBF -count=1 -v
GOSVM_UPDATE_FIXTURES=1 go test -ldflags=-linkmode=external ./internal/compiler -run TestSDKATACreateSBF
gosvm -o build/ata-create.so examples/ata-create
gosvm svm-test -elf build/ata-create.so -fixtures examples/ata-create/testdata/svm.json
```
