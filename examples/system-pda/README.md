# SDK-2 System PDA probe

This experimental fixture exercises the PDA-signed System helpers in
`gosvm/sdk/system`: `CreatePDA` over unfunded, partly funded and over-funded
addresses, a data-less System-owned vault (the shape Hyperlane's native-SOL
collateral and ATA-payer PDAs use), `TransferSigned` out of it, `AllocateSigned`
/`AssignSigned`, signer `Allocate`/`Assign`, wrong seeds and atomic rollback.
It is a runtime fixture, not application policy.

`testdata/svm.json` is generated by `TestSDKSystemPDASBF` in
`internal/compiler/sdksystem_sbf_test.go`, which also builds this package for
fogo-v0 and solana-v3 and runs every scenario against the real System program:

```sh
go test -ldflags=-linkmode=external ./internal/compiler -run TestSDKSystemPDASBF -count=1 -v
GOSVM_UPDATE_FIXTURES=1 go test -ldflags=-linkmode=external ./internal/compiler -run TestSDKSystemPDASBF
```

Or with the CLI, from the repository root:

```sh
gosvm -o build/system-pda.so examples/system-pda
gosvm svm-test -elf build/system-pda.so -fixtures examples/system-pda/testdata/svm.json
```

Drop `-ldflags=-linkmode=external` off macOS. The runner checks committed
state and exact errors; it does not model every rent state transition, so the
fixture does not assert that a partial drain below the rent minimum fails.
