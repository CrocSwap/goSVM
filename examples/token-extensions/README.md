# SDK-2 Token-2022 extension probe

This experimental fixture exercises extension-tolerant decoding in
`gosvm/sdk/token`: `ReadMint`, `ReadAccount`, `FindExtension`,
`ReadTransferFeeConfig` and `Fee`. It is a runtime fixture, not application
policy. Results are written to an 80-byte program-owned account.

- Real Token-2022 creates a transfer-fee mint and account; the fixture checks
  their exact bytes against the layouts the other scenarios preload, then
  decodes them.
- A raw `TransferChecked` on a transfer-fee mint at epochs 4 and 5 compares the
  SDK's fee with the amount Token-2022 credits and withholds (older fee, then
  the capped newer fee).
- Hyperlane's 234-byte metadata-pointer mint, a 170-byte `ImmutableOwner` ATA
  and classic Token accounts decode; type mismatches, absent extensions and an
  overrunning TLV entry are rejected.

`testdata/svm.json` is generated by `TestSDKTokenExtensionsSBF` in
`internal/compiler/sdktokenext_sbf_test.go`, which runs it on fogo-v0 and
solana-v3 against the Token-2022 8.0.0 image bundled with LiteSVM 0.8.2:

```sh
go test -ldflags=-linkmode=external ./internal/compiler -run TestSDKTokenExtensionsSBF -count=1 -v
GOSVM_UPDATE_FIXTURES=1 go test -ldflags=-linkmode=external ./internal/compiler -run TestSDKTokenExtensionsSBF
gosvm -o build/token-extensions.so examples/token-extensions
gosvm svm-test -elf build/token-extensions.so -fixtures examples/token-extensions/testdata/svm.json
```
